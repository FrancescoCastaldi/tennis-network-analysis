# Contributing

This is a five-person course project with one deliverable: the report in `report/main.tex`.
These rules keep the numbers in the report traceable to the code that produced them.

## Roles

The course grades three areas (20/60/20). Each member leads one role and supports others.

| Code | Area (weight) | Role | Report sections (words) |
|---|---|---|---|
| A | Context and problem (20%) | Context, problem and motivation | Introduction, Problem and Motivation (950) |
| B1 | Data and results (60%) | Datasets, validity and reliability | Datasets, Validity and Reliability (1,000) |
| B2 | Data and results (60%) | Measures and their justification | Measures and Results: measures (1,000) |
| B3 | Data and results (60%) | Hypotheses, tests and results | Measures and Results: tests (850) |
| C | Interpretation (20%) | Interpretation and critique | Conclusion, Critique (950) |

Progress is tracked in the group's Google Sheet ("SNA - UNIBO"); issues and milestones here mirror
it for code and report work.

*Note on collaborative drafting*: Francesco (B1) established the data pipeline, tests, and the drafts for
Datasets and Validity & Reliability. The text currently in Section 5 (*Measures and Results*) is an initial
technical working scaffold derived from pipeline outputs: Jacopo (B2) and Gaetano (B3) hold full editorial
ownership to revise, rewrite, or condense this text to balance the overall group word budget. Sections 1, 2,
6, and 7 are reserved for Shivam (A) and Paolo (C).

## Workflow

1. Open or pick an issue, set its role and phase labels and its milestone.
2. Branch from `main`: `feat/<topic>`, `fix/<topic>`, `docs/<topic>` or `report/<section>`.
3. Commit with [Conventional Commits](https://www.conventionalcommits.org/):
   `feat(hypotheses): add size-corrected grass test`, `docs(report): draft Validity section`.
4. Open a pull request and fill every section of the template. The `PR check` workflow fails on an
   incomplete body or a title that is not a Conventional Commit; CI must be green and one other member
   must approve. Fixes after a review go on the same branch, with a reply to each review thread.
5. Squash-merge into `main`. Never push directly to `main`.

## Rules for results

- Every number in the report comes from a file in `results/`. If it is not there, add it to the
  pipeline first.
- `report/tables/` and `report/figures/` are generated by `python -m tennis_networks.report_assets`.
  Do not edit them by hand.
- Randomness always goes through the seed in `config/networks.json`.
- Raw files in `data/raw/` are never modified. New sources are added with their URL, download date
  and SHA-256 in `docs/data.md`.
- Analysis is frozen at the end of the Analysis phase: after that, only bug fixes change `results/`.

## Writing rules

- Academic English, 12 pt, at most 5,000 words in total (`python -m tennis_networks.wordcount`).
- At most six figures. Every figure and table is referenced in the text.
- Report names, emails and student ID numbers only in the title block of the final PDF.

## Local setup

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pre-commit install
```

`pre-commit` runs Ruff (lint and format) and basic file checks before every commit.
